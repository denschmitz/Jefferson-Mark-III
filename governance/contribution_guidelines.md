# Contribution Guidelines

## Principles

- Treat `charter/charter.md` as the canonical source.
- Keep derivative documents aligned with canonical text.
- Prefer small, reviewable changes with clear rationale.
- Record substantive updates in `charter/versioning.md`.

## Workflow

1. Draft or revise the canonical charter text.
2. Update annotations if the rationale changed.
3. Update derivative documents affected by the change.
4. Record the change in the version history.

## Review Expectations

- State the problem being solved.
- Identify any normative or governance assumptions.
- Call out downstream impacts on simulation or explainers.
- Flag unresolved issues explicitly.
